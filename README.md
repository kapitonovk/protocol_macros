# Финализация сборки протокола — что делать

## 1. Правки в make_appx (3 строки, логика не тронута)

В `RunAppendixOnly` — путь к шаблону приложения:

```vba
' было
If Trim(CStr(numVal)) = "0.2" Then
' стало
If Trim(CStr(numVal)) = "0.4" Then
```

В `GetDocRefValue` — служебные таблицы:

```vba
' было
If UCase(conditionText) = "ДДУ" Then
    filePath = GetSourcePathByNumber(wbMain, "0.4")   ' -> ddu_data = 0.6
ElseIf UCase(conditionText) = "ДКП" Then
    filePath = GetSourcePathByNumber(wbMain, "0.3")   ' -> ПОДБОР писем = 0.5

' стало
If UCase(conditionText) = "ДДУ" Then
    filePath = GetSourcePathByNumber(wbMain, "0.6")
ElseIf UCase(conditionText) = "ДКП" Then
    filePath = GetSourcePathByNumber(wbMain, "0.5")
```

Больше в make_appx ничего не меняется. Всё, чего он не закрывает
(`{{I}}`, `{{КВАРТИРЫ_СЧЕТ}}`, блок 1.x.4 для не-ДДУ), дорабатывается
пост-обработкой в make_report.

## 2. Импорт модулей

- `make_body` — заменить целиком содержимым `make_body.txt`.
- `make_report` — новый модуль, содержимое `make_report.txt`.
- Точка входа: `BuildProtocol` (можно повесить на кнопку на листе Config).

Важно: в новом `make_body` удалены дубли `ColLetterToIndex`,
`FindHeaderColumn`, `FindSourceRowByNumber`, `GetDataScalarByPlaceholder`,
`ReplacePlaceholderInWord` — они остаются жить в make_appx. Без этого
вызов из третьего модуля даёт compile error «Ambiguous name detected».

## 3. Флаги в шапке make_report

```vba
Private Const FIX_HARDCODED_SECTION_NUMBERS As Boolean = True
Private Const DROP_DDU_BLOCK_FOR_NON_DDU   As Boolean = True
Private Const SHOW_RESULT                  As Boolean = True
```

- `FIX_HARDCODED_SECTION_NUMBERS` — заменяет в тексте жёстко прописанные
  «п. 1.1.1», «Приложению 1.1.2», «Приложении № 1.1.3» на номер текущего
  источника. Костыль на время; правильнее проставить в шаблонах `1.{{I}}.x`
  и выключить флаг.
- `DROP_DDU_BLOCK_FOR_NON_DDU` — для источников с Тип ≠ ДДУ вырезает из
  копии приложения блок «Приложение № 1.x.4» (рассрочка) вместе с Table 6,
  как и предполагает формула в Sources (столбец «Приложение 1.x.4»).

## 4. Как работает сборка

1. Читает Sources: 0.1 титул, 0.2 body, 0.3 лист согласования, 0.4 приложение.
2. Считает data-источники: строки, где «Номер» без точки (1, 2, 3 …),
   «Файл» заполнен и файл реально существует (`Dir`). Пустые строки 2…10
   просто игнорируются, количество источников любое.
3. Master-документ создаётся из титульника, в него подставляются
   `{{ПРОТ_НОМЕР}}`, `{{ДАТА1}}`, `{{ДАТА1ФОРМАТ}}`, `{{ДАТА2}}`.
4. Для каждого источника: data-файл открывается read-only →
   `BuildBodyDoc` (make_body) и `BuildSection_1_1_APPX` (make_appx) →
   пост-обработка номеров разделов → часть сохраняется во временный docx.
5. Лист согласования — отдельная часть.
6. Мердж в порядке: титул → body₁..N → лист согласования → приложение₁..N.
   Каждая часть вставляется через `Range.InsertFile` после разрыва раздела
   «со следующей страницы» — поэтому альбомные секции приложения не ломают
   портретный body.
7. Результат сохраняется рядом с main.xlsx:
   `protocol_<номер>_<ггггммдд_ччмм>.docx`, временные файлы удаляются,
   data-файлы закрываются без сохранения.

## 5. Мелочи, которые стоит поправить в шаблонах

- `template.appendix.docx`, абзац «Приложение № 1.{{I}.3» — не хватает
  закрывающей скобки. Код это уже подстраховывает (`1.{{I}.` → `1.N.`),
  но лучше починить в шаблоне.
- В body «в п. 1.1.1» и в приложении «Приложению 1.1.2 / № 1.1.3» —
  заменить на `1.{{I}}.x`.
- `FormatDateForProtocol` даёт «01» январь 2000 (Format "mmmm" в RU-локали
  выдаёт именительный падеж). Если нужен родительный — скажи, добавлю
  массив названий месяцев.

# Правки по bugs_20260803

## 1. Лишний «№ п.п.» в таблице body

В шаблоне колонка 1 — нумерованный список Word. Список продолжается сквозь
все склеенные body-таблицы (отсюда сквозная нумерация), а поверх него VBA
пишет свой номер — получается дубль.

Сделано в `make_body`: перед заполнением с колонки 1 снимается автонумерация
(`ListFormat.RemoveNumbers`, с поячеечным фоллбэком на случай merged cells),
номера пишет VBA — 1..N внутри каждой таблицы. Правка шаблона не требуется,
но если уберёшь список в шаблоне сам — ничего не сломается.

Флаги в шапке модуля:

```vba
Private Const WRITE_ROW_NUMBERS          As Boolean = True  ' номера пишет VBA
Private Const STRIP_LIST_NUMBERING_IN_COL1 As Boolean = True
```

Если захочешь наоборот — оставить нумерацию Word и не писать её из VBA:
`WRITE_ROW_NUMBERS = False`, `STRIP_LIST_NUMBERING_IN_COL1 = False`. Тогда
нумерация останется сквозной по всему протоколу.

## 2–4. Потеря оформления при мердже

### Почему так было

`Range.InsertFile` **не импортирует стили**. Вставляемый текст сохраняет
имена стилей, но начинает подчиняться определениям стилей master-документа,
а master создавался из титульника. Отсюда:

- кегль основного текста и подзаголовков «Приложение» уезжает — эти абзацы
  оформлены стилем, определение которого в титульнике другое;
- где поверх стиля было прямое форматирование, оно уцелело → потери
  «неоднородные», ровно как ты описал;
- при visible = True отдельный appendix выглядит правильно, потому что там
  ещё действуют стили его собственного шаблона.

Отдельная причина съехавших альбомных таблиц: параметры страницы **последней**
секции документа хранятся в его финальном знаке абзаца. `InsertFile` их не
переносит, поэтому альбомный блок APPX_113b оказывался в портретной секции,
и таблица, свёрстанная под ~26 см, ломалась. «Последний адрес выглядит
нормально» — тот же механизм: у хвоста документа page setup случайно
совпадал с оставшимся.

### Что сделано в make_report

`AppendFileToMaster` заменён на `AppendPartToMaster`:

1. часть открывается как отдельный документ;
2. в master добавляется разрыв раздела «со следующей страницы», в новую
   секцию копируется `PageSetup` первой секции части (ориентация, размер,
   поля, колонтитульные отступы), колонтитулы отвязываются от предыдущей
   секции;
3. содержимое части (без финального ¶) вставляется через буфер как
   `PasteAndFormat wdFormatOriginalFormatting` — Word разрешает конфликт
   стилей в пользу источника, превращая расхождения в прямое форматирование,
   поэтому кегли, интервалы и таблицы остаются как в шаблоне;
4. после вставки в последнюю секцию master копируется `PageSetup` последней
   секции части — это и чинит альбомные листы;
5. вставка через буфер обёрнута в ретраи (5 попыток с паузой) — клипборд
   иногда занят сторонним процессом.

Флаги:

```vba
Private Const MERGE_KEEP_SOURCE_FORMATTING As Boolean = True  ' False = старый InsertFile
Private Const COPY_HEADERS_FOOTERS         As Boolean = True
```

Старый способ сохранён в `AppendFileToMaster_Legacy` — на случай отката.

### Что проверить после прогона

- альбомные секции приложения: ориентация и ширина таблицы APPX_113b;
- кегль основного текста в body и в подзаголовках «Приложение»;
- отсутствие пустых страниц на стыках (хвостовые ¶ подрезаются, финальный ¶
  части в буфер не попадает);
- нумерация «№ п.п.» в каждой таблице body начинается с 1.

### Если где-то оформление всё же поплывёт

Радикальное лекарство — привести все четыре шаблона к одному набору стилей
(сделать их из одного базового файла, чтобы `Normal`, «Обычный», стиль
таблиц и т. п. имели одинаковые определения). Тогда конфликт стилей
исчезает в принципе и способ мерджа перестаёт иметь значение. Клипбордная
вставка это маскирует прямым форматированием, но чистое решение — единая
база стилей.
